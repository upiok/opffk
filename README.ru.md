## Установка

### Что нужно

- Роутер Keenetic с **установленным Entware** (веб-интерфейс Keenetic →
  *Другие установки* → *Entware*, на USB-накопитель или внутреннюю память)
  и доступом по SSH под `root`.
- **Поддерживаемая архитектура CPU** (`uname -m` по SSH): `aarch64` или
  `armv7l` — см. [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md).
  Роутеры на MIPS **не поддерживаются** (апстрим не публикует MIPS-бинарники).
- **ОЗУ**: минимум 128 МБ свободно, лучше 256 МБ.
- **Память**: 150 МБ свободно под `/opt` (одно ядро апстрима ~25 МБ).
- systemd, bash, Docker, Python и Node.js не нужны. Установщику нужны
  POSIX `sh`, `curl` или `wget` (с HTTPS), `tar` и утилита `sha256` — всё
  это уже есть в Entware или ставится одной командой `opkg install`.

### Одна команда



```sh
curl -fsSL https://raw.githubusercontent.com/upiok/opffk/main/install.sh \
  | OPFFK_REPO=upiok/opffk sh
```

### Что делает установщик

1. Определяет Entware, архитектуру, ОЗУ, место на диске и нужные утилиты;
   всё неподдерживаемое отклоняет с понятной диагностикой.
2. Скачивает и проверяет релиз (если не указан `--from-dir`).
3. Делает бэкап прежней конфигурации (`/opt/var/lib/opffk/`).
4. Ставит бинарники, init-скрипт (`/opt/etc/init.d/S99opffk`) и закреплённый
   `manifest.json` ядра апстрима.
5. Создает непривилегированную учётную запись сервиса `openflux` в
   `/opt/etc/passwd` (файл passwd Entware переживает перезагрузки Keenetic,
   в отличие от `/etc/passwd` прошивки). Бэкенд сбрасывает root на этого
   пользователя при старте.
6. Запускает сервис, ждёт готовности и **один раз** печатает начальный
   пароль веб-интерфейса.

### Первый вход

1. Откройте `http://<LAN-IP-роутера>:8791` с устройства в вашей LAN.
2. Войдите с напечатанным одноразовым паролем (он перестаёт действовать
   после первого входа; `sh install.sh reset-password` генерирует новый).
3. Смените пароль в разделе *Settings*.

Веб-интерфейс слушает **только LAN-адрес роутера** и недоступен из интернета
(WAN). opffk никогда не меняет настройки Keenetic — файрвол, проброс портов,
маршрутизацию и DNS; подробности в [docs/SECURITY.md](docs/SECURITY.md)
(на английском).

## Настройка (веб-интерфейс)

- **Режим ноды**: `l4` (userspace gVisor — поддерживается, root не нужен).
  `l3` существует в апстриме, но заблокирован: требует root, iptables и
  явного `allow_l3` в `ui.json`, и конфликтует с собственным NAT Keenetic.
- **Egress-прокси** (возможность ядра форка): исходящий TCP ноды идёт
  через ваш SOCKS5/HTTP-прокси (URL в поле *Egress proxy*). Только TCP —
  UDP отклоняется, пока прокси задан (клиенты уходят в DNS по TCP).
  Работает только с `l4`. Появилось в сборке ядра
  `node-v1.4.0-opffk.1`; в апстриме такой возможности нет.
- **Транспорты**: `direct` (свой сервер, работает всегда, рекомендуемый
  первый) плюс типыcarrier'ов, которые поддерживает апстрим (`yandex`,
  `vyandex`, `mailru`, `cupsonline`, `boards`, `avito`, `telemost`,
  `oneme`). Нужен хотя бы один транспорт; ключ шифрования генерируется и
  управляется автоматически.
- Каждое изменение проверяется по правилам закреплённой версии апстрима
  *до* записи; неверный ввод никогда не трогает конфиг ядра.
- **Apply** пишет `/opt/etc/opffk/openflux.conf` (INI-формат апстрима);
  **Apply & restart** ещё и перезапускает ядро.
- **Client link** генерирует ссылку `openflux://` через родной
  `--make-link` ядра — для вставки в клиентские приложения OpenFlux.
  Ссылка содержит ключ шифрования — обращайтесь с ней как с паролем.
  *Rotate encryption key* делает все прежние ссылки недействительными.

Пример сгенерированного конфига (полный справочник с комментариями:
[docs/openflux.conf.example](docs/openflux.conf.example)):

```ini
Role = exit
Mode = l4
EncryptionKeyFile = /opt/etc/opffk/encryption-key
CookieStore = /opt/var/lib/opffk/cookies.json
Debug = 2
Codec = batched

[Transport direct]
Type = direct
Priority = 50
Listen = 0.0.0.0:7891
```

### Доступ к ноде из интернета (по желанию)

Нода слушает `0.0.0.0:<порт>` (транспорт `direct`). Чтобы клиенты могли
подключаться извне, создайте **проброс TCP-порта** в веб-интерфейсе
Keenetic сами (*Сетевые правила → Проброс портов*, WAN → выбранный порт →
IP роутера, порт 7891). opffk намеренно этого не делает.

## Обновления, откат, удаление

- **Обновления ядра** (карточка *Core updates*): скачивает закреплённый
  релиз апстрима из настроенного манифеста, проверяет SHA-256, подменяет
  бинарник, перезапускает и проверяет здоровье; при неудачной проверке
  откатывается автоматически. Кнопка *Roll back* возвращает предыдущий
  бинарник в любой момент. Чтобы проверки работали, задайте
  `update_manifest_url` в `ui.json` (или ставьте свежие релизы установщиком).
- **Обновления самого бэкенда**: повторно запустите установщик
  (`install.sh upgrade` — обычный `install` идемпотентен и сохраняет
  конфигурацию).
- **Удаление**: действие в веб-интерфейсе с подтверждением (ввести
  `UNINSTALL`) или `sh install.sh uninstall`. Оба сначала делают бэкап
  конфигурации. Логи и бэкапы в `/opt/var/log/opffk` и
  `/opt/var/lib/opffk` остаются и перечисляются для ручного удаления.

## Управление сервисом из CLI

```sh
/opt/etc/init.d/S99opffk {start|stop|restart|status}
sh install.sh status          # состояние установки
sh install.sh reset-password  # новый одноразовый пароль веб-интерфейса
```

Логи: `/opt/var/log/opffk/core.log` (+`.1` при ротации), `web.log`,
`console.log`.

## Если что-то не работает

| Симптом | Причина / решение |
|---|---|
| `architecture ... is not supported` | Устройство на MIPS или armv6 — апстрим не публикует такие бинарники; см. docs/COMPATIBILITY.md |
| `no Entware found at /opt` | Сначала установите Entware в веб-интерфейсе Keenetic |
| `web UI port ... already in use` | Перезапустите установщик с `--port N` |
| UI не открывается из LAN | Неверный адрес привязки: перезапустите с `--listen-ip <LAN-IP-роутера>`; смотрите `/opt/var/log/opffk/console.log` |
| Ядро падает / перезапускается бесконечно | `cat /opt/var/log/opffk/core.log`; обычно неверный URL/токен транспорта или мало ОЗУ |
| Клиент не подключается из интернета | Не настроен проброс порта (делается в веб-интерфейсе Keenetic вручную) или у провайдера CGNAT |
| Забыли пароль веб-интерфейса | `sh install.sh reset-password` |
| `service account "openflux" not found` | Файл passwd Entware был восстановлен/обрезан — перезапустите установщик |

## Безопасность

Кратко (полная модель — в [docs/SECURITY.md](docs/SECURITY.md), на
английском):

- На каждом маршруте требуется вход; хранится только хеш PBKDF2-HMAC-SHA256
  (120 000 итераций); ограничение попыток входа; одноразовый начальный
  пароль.
- CSRF-защита (double-submit + проверка Origin) на всех изменяющих
  маршрутах; строгий CSP; ввод пользователя никогда не передаётся в shell.
- Секреты (`encryption-key`, `ui.json`) — `0600`, конфиги — `0640`.
- Сброс прав на пользователя сервиса `openflux`; ядро работает без
  привилегий (возможно благодаря userspace-режиму `l4`).
- UI привязан только к LAN; автоматических изменений настроек Keenetic нет.
