Configuration

Values are validated against the pinned upstream OpenFlux rules before anything is written. The core config lives at .

l3 caveats: needs root or CAP_NET_RAW (set "run_as": "" in ui.json and restart the backend), is experimental on Keenetic (the router's own NAT sees the SNAT'd flows), and cannot use the egress proxy. Upstream also recommends dropping kernel RSTs for the egress IP — run in the Entware shell yourself:
iptables -A OUTPUT -p tcp --tcp-flags RST RST -s <egress-ip> -j DROP

Client link

Generate an openflux:// link for client apps. The link contains the encryption key — treat it like a password and share it over a trusted channel only. Generating a new key invalidates every existing client link.

Core updates

Updates download the pinned upstream core (), verify its SHA-256 against the signed-in manifest, restart the service and roll back automatically if the new core does not come up healthy. Backend updates: re-run install.sh upgrade over SSH.
